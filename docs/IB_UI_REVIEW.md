# IB UI 검토 기록

2026-10-04 · PIN 읽기 전용 로컬 구현 · Impeccable 확장 문서화

`/ib`는 기존 HowNote/Care의 시각 언어를 이어받은 개인 읽기 전용 연구 블로그다. 사용자는 숫자 4자리 PIN으로 읽고, 도비는 별도 게시 API/MCP 권한으로 연구와 과목을 기록한다. 현재 기준은 [PRODUCT.md](../PRODUCT.md)와 [IB_RESEARCH.md](IB_RESEARCH.md)다. 이번 문서화는 IB 화면에 한정하며 루트 디자인 시스템을 새로 정의하지 않았다.

## 기존 디자인과의 연속성

Care의 Inter 및 한국어 시스템 글꼴 스택, 종이색 배경(`#f6f5f0`), 짙은 본문색(`#1d302c`), 녹색 강조(`#1e5c49`)를 유지한다. 공개 HowNote의 녹색 중심 팔레트와도 연결된다. 얇은 구분선, 절제된 둥근 모서리, 텍스트 중심 목록으로 읽기 흐름을 만든다. IB 구분선은 `#d9ded5`, 입력 배경은 `#fdfcf8`, 요약·선택 배경은 `#e8eee5`다. 이 값들은 `src/styles/ib.css`의 구현 사실이며 전역 규칙으로 확대하지 않는다.

기존 대비 수정을 유지한다. 필드 테두리는 `#7a8b7e`, 보조 텍스트와 placeholder는 `--muted: #56675e`, placeholder 불투명도는 1이다. 앞선 기계 검사에서 나온 Inter 경고는 기존 정체성과의 연속성에 따라 유지했다.

## 읽기와 조작 동작

- **읽기:** 날짜별 목록과 분류 메뉴를 중심으로 탐색한다. 과목 탭은 동일한 연구 기록을 참조한다. 상세는 요약 → 본문 → 문항 설계 정보 → 출처·이용범위 → 변경·검수 이력 순서이며, 본문은 최대 `72ch`, 줄 높이 `1.95`다. 이전 버전도 읽을 수 있고 게시자 이력은 내부 토큰 식별자 대신 ‘도비’ 또는 ‘자료 게시’로 표시한다.
- **PIN:** ASCII 숫자 네 자리만 받으며 앞의 0을 보존한다. 입력칸은 처음부터 비어 있는 마스킹 필드이고, `inputmode="numeric"`으로 모바일 숫자 키보드를 요청한다. 명시적 레이블과 56px 입력 높이, 주요 44px 조작 영역을 사용한다. 성공·실패·연결 오류 뒤 PIN을 지우고 연결 실패에는 재연결 안내를 표시한다. 시도 제한 시 남은 대기 시간과 비활성 입력·버튼을 보여주며 새로고침으로 서버 제한을 해제할 수 없다.
- **읽기 권한:** 화면에서 작성·수정·과목 관리 폼과 버튼을 제거했다. 웹 세션의 연구·과목 POST/PUT/PATCH/DELETE는 서버에서 403으로 차단하며 PIN은 도비 게시 권한이 아니다. 공개 가입·최초 설정·PIN 변경 경로는 없고 PIN 미설정 시 로그인은 503으로 닫힌다. `/ib/edit` 북마크는 ‘연구 기록은 도비가 정리합니다’ 안내와 목록 링크를 유지한다. `/ib/subjects`는 과목 후보·개설 근거·보관·변경 이력을 읽는 화면이며 표시 순서는 인기 순위가 아니다.
- **반응형:** 데스크톱은 사이드 메뉴와 읽기 영역의 두 열이다. 740px 이하에서는 분류·과목 탭이 가로 스크롤되고 날짜·본문·설계 정보가 한 열로 정리된다. 긴 표는 자체 영역에서 가로 스크롤한다. 본문 이동 링크와 명시적 키보드 포커스 스타일도 구현되어 있다.

## 확인 근거와 범위

직접 열어 확인한 최신 캡처는 `artifacts/ib-pin/`의 [로그인 데스크톱](../artifacts/ib-pin/login-desktop.png)·[모바일](../artifacts/ib-pin/login-mobile.png), [목록 데스크톱](../artifacts/ib-pin/desktop.png)·[모바일](../artifacts/ib-pin/mobile.png), [상세 데스크톱](../artifacts/ib-pin/detail-desktop.png)·[모바일](../artifacts/ib-pin/detail-mobile.png) 6개다. 로그인은 빈 PIN 상태이고 연구는 자체 작성 로컬 fixture다. 실제 IB 기출·개설 현황의 검증 자료는 아니다. 현재 레이아웃, IB 페이지, `src/scripts/ib.ts`, 스타일과 브라우저 테스트를 대조했다. 이전 `artifacts/ib/` 캡처는 PIN 변경 전의 역사적 자료다.

최종 작업 세션에서 `npm run validate`와 `npm run check:ib`가 통과했다. `npm run test:private`는 PIN 설정·세션 30건, Care 31건, OAuth 39건, IB 저장·권한 141건, PIN 미설정 5건으로 총 246건 통과했다. Playwright의 Chrome 브라우저 5개 흐름도 통과했다. 1440px 데스크톱과 390/360px 모바일에서 PIN 입력 속성·초기 빈 값, 탐색·필터·공유 과목 참조·상세·버전, 별도 도비 게시와 재시도, 과목 안내·보관 이력, 읽기 전용 경계·위험한 Markdown·빈 결과·로그아웃·대기 제한·연결 오류 안내를 검사했다. 검색 입력의 계산 스타일에서 테두리 3:1 이상, placeholder 4.5:1 이상과 페이지 가로 넘침도 확인했다.

후속 화면 검토는 연결 오류의 읽기용 안내·PIN 삭제와 게시자 표기의 두 수정 및 최신 캡처 6개를 재검토해 `SHIP`으로 판정했다. 이 판정은 해당 수정과 캡처에 근거한 UI 인수 범위에 한정된다.

근거는 자동 테스트와 설치된 Chrome·Playwright의 캡처이며 후속 검토에서 브라우저를 독립 재실행한 결과는 아니다. 실제 모바일 키보드, Computer Use, 스크린리더 또는 전체 접근성·보안·운영 배포 인증을 수행한 결과로 해석하지 않는다. 전체 `astro check`에는 기존 `src/components/PurchaseNoteHandoff.astro:41`의 implicit-any 오류 1건이 남아 있고, IB 범위 8개 파일 검사는 오류·경고·힌트 0건이다. 실제 `.dev.vars`·사용자 PIN·인증 토큰을 설정하거나 변경하지 않았으며 기존 실제 설정 파일 해시도 유지했다. 운영 배포와 운영 DB 작업은 수행하지 않았다. 이번 갱신은 이 문서만 수정했다.
